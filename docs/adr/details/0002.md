# Details: 0002. Outcome write/read path follows the existing gaia controller pattern

## Considered options

- **A separate write API bypassing the gaia controller/indexer pattern** — rejected: would need
  its own MongoDB-to-SOLR sync, duplicating logic gaia's `upsertSchemaLinkages` /
  `queueLinkedSchemaReindex` fan-out already provides for every other linked schema.
- **Synchronous SOLR write from the API request** — rejected: couples the request/response cycle
  to indexer latency and loses the retry/queueing semantics the message-queue step already gives
  every other gaia-authored record.

## Decision drivers

- Reuse over reinvention: gaia's controllers already have a working, tested pattern for
  write-then-index-then-fan-out on linked schemas.
- The front end (`www.cbd.int-headless`) must stay a pure SOLR read-through with no direct
  gaia/Mongo coupling, consistent with `docs/coa-2026-07-09/CONTEXT-MAP.md`'s Customer/Supplier
  boundary (gaia → www is a Published Language over the Solr index only).

## Consequences

- One write path for Outcomes, consistent with every other gaia-owned record.
- Indexing latency (MongoDB write to SOLR-visible) is now user-visible to authors, since the
  activity + Outcomes only appear in the public search page once the indexer's message-queue
  step completes.
- The fan-out's existing coupling to the CBD relational store is decoupled as part of this work:
  the reverse-reindex now publishes a queued job and resolves codes asynchronously, so authoring
  latency no longer depends on SQL availability. This was formerly deferred item D4 and was pulled
  into scope — see "Pulled into scope" in `docs/coa-2026-07-09/prd.md`.
